## ⚠️ SSH — только из PowerShell
`ssh hetzner` работает **только из PowerShell**, не из Bash-инструмента.
- Ключ `~/.ssh/hetzner` зашифрован, лежит в Windows ssh-agent (именованный канал).
- PowerShell использует Windows OpenSSH → ключ из агента автоматически.
- Bash (POSIX/MSYS) ищет ключ через `SSH_AUTH_SOCK`, агент не запущен → `Permission denied`.

Проверка:
```powershell
ssh-add -l
ssh hetzner 'whoami'   # -> root
```

## ⚠️ Кавычки в SSH-командах из PowerShell
1. Удалённую команду оборачивать **одинарными** кавычками, без `"` внутри.
2. Не использовать `"`, `<`, `>` внутри команды — ломает парсинг.
3. Многострочные скрипты — через here-string в stdin (`bash -s`), не ставить `set -e` первой строкой (PowerShell может добавить BOM).

## Статика поверх лендинга (добавлено позже)
Всё это живёт в `/var/www/dacha-landing` и **не обновляется деплоем `dacha-api`** — нужен
отдельный шаг плюс свой `location` в nginx (иначе запрос уходит в catch-all `proxy_pass` на API
и возвращает 404 от Fastify — так было с favicon).

- **`/spravochnik/`** — 133 статические страницы культур и проблем,
  `backend/scripts/generate-spravochnik.js` (запускать после `backfill-crop-slugs.js`).
- **`/blog/`** — статьи контент-плана, `backend/scripts/generate-blog.js`
  (состояние — `scripts/.blog-manifest.json`, untracked, переживает `reset --hard`).
- **favicon** (2026-07-14): реальные `favicon.ico/svg/192/apple-touch-icon` + свой `location` —
  Яндекс.Вебмастер не распознавал прежнюю data-URI-иконку.
- **IndexNow**: `backend/scripts/submit-indexnow.js` шлёт URL из `sitemap.xml`; гонять после
  каждой новой партии страниц. Требует `INDEXNOW_KEY` и файл-подтверждение в корне сайта.

Оба генератора мержат `sitemap.xml` каждый по своей зоне URL — не затирая записи друг друга.

## Веб (SPA)
```powershell
ssh hetzner 'cd /var/www/dacha-api/web && npm ci && npm run build && rm -rf /var/www/dacha-web/* && cp -r dist/* /var/www/dacha-web/'
```
Отдельный шаг от деплоя бэкенда: `reset --hard` обновляет исходники, но не пересобирает бандл —
забытая пересборка уже приводила к тому, что фича «была в проде», а пользователи её не видели.
